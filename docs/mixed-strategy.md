# 混合策略

不是所有内容都需要同步。本项目主张**按内容性质分流**，而不是用一个方案
覆盖全部。

## 三类内容

| 类别 | 特征 | 方案 | 原因 |
|---|---|---|---|
| **会话状态** | 需要实时一致、双向 | Agent 同步 | 有冲突、有时序、需去重 |
| **笔记与配置** | 只增不改、可人工仲裁 | Git | 版本化、可回滚、文本友好 |
| **大文件与二进制** | 体积大、不常变 | Tailscale 直传 / 手动 | 不适合进版本库 |

## 划分原则

### 用 Agent 同步的

- 会话历史、上下文
- Agent 记忆与偏好
- 技能配置、工具开关
- 需要在两台机器间**保持一致**且**经常变动**的内容

判断标准：**两台机器上应该看起来一样，且变化需要自动传播。**

### 用 Git 的

- 笔记（Markdown 文档）
- 配置文件（`dotfiles`、编辑器配置）
- 脚本与代码
- 文档

判断标准：**内容是文本，需要历史记录和回滚能力，可以接受手动合并。**

实践上：单个 Git 远端 → 两台机器 `pull`/`push`。

### 用 Tailscale 直传的

- 模型权重、数据集、图片、视频
- 数据库备份
- 安装包

判断标准：**体积大、不常变、不需要版本历史。**

```bash
# 直接经 Tailscale 地址传输，走 WireGuard 加密通道
rsync -avP -e ssh large-file.tar.zst <peer>:~/dest/
```

或用 `scp`、`rclone`。

## 为什么不统一成一种

| 方案 | 优点 | 局限 |
|---|---|---|
| Agent 同步 | 自动、幂等、处理冲突 | 只适合结构化状态 |
| Git | 版本化、可回滚、文本 diff | 不适合频繁变动的运行时状态 |
| Tailscale 直传 | 大文件、点对点加密、不走网盘 | 无版本、手动触发 |

**用错方案的代价**：

- 会话状态用 Git → 频繁冲突、二进制 diff 无意义
- 笔记用同步 → 丢失历史与回滚能力
- 大文件用 Git → 仓库膨胀

## 实际搭配示例

```text
Agent 会话状态  → 本项目（Collector/Receiver）
笔记与配置      → Git + 同一个远端仓库
模型与数据集    → rsync over Tailscale
密码与密钥      → 不同步，各机独立管理（或用密码管理器）
```

## 凭据处理

**不要同步凭据。** 各机独立管理，或使用支持端到端加密的密码管理器
（1Password / Bitwarden 等）。

若确实需要在多机共享同一份 API Key，用密码管理器，不要写进同步内容。
本项目的 schema 白名单也从设计上排除了这类字段，见 [安全设计](security.md)。

## 定期回顾

内容的性质会随项目演进变化。定期检查：

- 同步列表里是否有本不该同步的（尤其是新增字段）
- 有没有大文件被误加进 Git
- 有没有配置该进 Git 却在手动复制
