# 架构设计

## 总览

三段式：**采集（Collector）→ 传输（Tailscale）→ 应用（Receiver）**。

```text
┌───────────────────────────┐        Tailscale WireGuard        ┌───────────────────────────┐
│       macOS / 发送端       │ ───────────────────────────────► │      Linux / 接收端        │
│                           │     点对点直连，中继兜底            │                           │
│  ┌─────────────────────┐  │     无公网端口暴露                 │  ┌─────────────────────┐  │
│  │  Agent 本地状态库    │  │                                   │  │  验签 / 去重          │  │
│  │  (只读)             │  │    HMAC 签名 + 单调序列号           │  └──────────┬──────────┘  │
│  └─────────┬───────────┘  │    断网重试 / 幂等投递               │             ▼             │
│            ▼              │                                   │  ┌─────────────────────┐  │
│  ┌─────────────────────┐  │                                   │  │  同步库 (落库)        │  │
│  │  schema 白名单抽取   │  │                                   │  └──────────┬──────────┘  │
│  └─────────┬───────────┘  │                                   │             ▼             │
│            ▼              │                                   │  ┌─────────────────────┐  │
│  ┌─────────────────────┐  │                                   │  │  Agent 启动时读取     │  │
│  │  outbox (本地队列)   │──┼───────────────────────────────────┼─►│  统一状态              │  │
│  └─────────────────────┘  │                                   │  └─────────────────────┘  │
└───────────────────────────┘                                   └───────────────────────────┘
```

## 组件

### 1. Collector（采集端）

职责：安全地从本机 Agent 读取状态并投递到对端。

| 模块 | 职责 |
|---|---|
| Schema 白名单 | 只读取 `collector.json` 中声明的字段；未授权字段直接拒绝 |
| 只读快照 | 以只读方式打开源库，不加写锁，不影响 Agent 运行 |
| 序列化 | 生成不可变快照，写入 outbox |
| Outbox 队列 | 本地持久化队列，断网时排队，恢复后补发 |
| 签名 | 对每条消息做 HMAC 签名 |

**失败模式**：源库被占用 → 只读重试；schema 不匹配 → 拒绝并告警，不静默降级。

### 2. 传输层（Tailscale）

职责：在两台设备间建立安全通道。

- 全流量走 WireGuard 隧道，端到端加密
- 服务只监听 Tailscale 网卡地址或 `127.0.0.1`
- **不向公网暴露任何端口**
- 直连优先，失败自动回退 DERP 中继

路径选择逻辑与优化方法见 [Tailscale 直连方案](tailscale-direct.md)。

### 3. Receiver（接收端）

| 模块 | 职责 |
|---|---|
| 验签 | HMAC 校验，失败即丢弃 |
| 序列号去重 | 单调序列号，重复即丢弃，保证幂等 |
| 落库 | 写入本地同步库 |
| 应用 | Agent 启动时读取 |

## 数据流

```text
1. Collector 读取源库 → schema 校验 → 生成快照
2. 快照入 outbox，分配单调序列号
3. 通过 Tailscale 隧道发送，附带 HMAC 签名
4. Receiver 验签 → 去重 → 落库
5. Agent 启动读取，状态一致
```

断网时第 3 步失败，消息停留在 outbox；恢复后重发，Receiver 通过序列号去重，
**保证不丢不重**。

## 信任边界

```text
┌─ 本机信任域 ─────────────┐   ┌─ 网络传输域 ─┐   ┌─ 对端信任域 ─────────────┐
│ Agent 状态库（只读）      │──►│ Tailscale    │──►│ 验签 + 去重              │
│ schema 白名单             │   │ WireGuard    │   │                          │
│ 密钥永不出域              │   │ 端到端加密    │   │ 只接受本 tailnet 成员     │
└──────────────────────────┘   └──────────────┘   └──────────────────────────┘
```

密钥与凭据**永不出域**：采集端在 schema 层就拒绝读取，不进入 outbox，更不进入传输。
详见 [安全设计](security.md)。

## 失败模式

| 故障 | 影响 | 应对 |
|---|---|---|
| 网络断开 | 投递失败 | outbox 排队，恢复后补发 |
| 走中继 | 延迟升高 | 自动回退，可用性不受影响 |
| 对端离线 | 投递失败 | 重试 + 排队，不影响本机 |
| 序列号重复 | 潜在重复 | Receiver 去重丢弃 |
| 签名错误 | 潜在篡改 | Receiver 拒收 |
| 源库被占用 | 读取失败 | 只读模式重试 |
| schema 漂移 | 字段不匹配 | 拒绝并告警，不静默降级 |

## 扩展点

### 适配其他 Agent

同步层只依赖"存在一个本地状态库"。适配新 Agent 只需提供一份 schema：

```json
{
  "fields": ["id", "title", "created_at"],
  "excluded": ["api_key", "token", "path"]
}
```

### 三端及以上

当前为双端对称架构。多端扩展需引入：

- 单一主节点或冲突解决策略
- 各端序列号空间的协调

### 增量同步

当前为全量快照 + 序列号去重。数据量增长后可改为基于变更日志的增量同步。

## 技术选型

| 组件 | 选型 | 理由 |
|---|---|---|
| 通道 | Tailscale | 免公网 IP、自动打洞、配置成本低 |
| 传输 | WireGuard | 内核态加密，开销低 |
| 签名 | HMAC-SHA256 | 对称密钥即可，无需 PKI |
| 队列 | SQLite outbox | 事务保证、崩溃安全 |
| 服务管理 | systemd / launchd | 原生开机自启 |
| 反向代理 | aiohttp | 轻量，支持请求头适配 |
